## Scope and boundaries

Implement ENV007–ENV012, expanded Docker/dependency evidence, `explain` and `rules --json`.
M2 already has the local-default Docker probe for ENV006, seven collectors and six pure rules.
Interactive reporting/bundles remain M4; automatic remediation remains M5; packaging remains M6.
No collector or rule edits PATH, profiles, Git config, Docker state or installed packages.

## Evidence required for each rule

| Rule | Required evidence and decision |
|---|---|
| ENV007 | Known client/server API compatibility ranges or an explicit API override that the daemon cannot support. Different product version strings alone are not a failure. Record the supported API policy and source. |
| ENV008 | A detected project with an explicit, supported requirement for a named tool/library, plus a reliable platform presence check. A language extension alone does not imply every compiler/library is required. |
| ENV009 | Declared package manager/version or explicitly selected runner and observed lockfiles. A lockfile plus installed npm does not establish that npm is the runner. Conflicting lockfiles need a distinct explanation. |
| ENV010 | Effective Git identity and its config origin; autocrlf advice requires an explicit project policy/attributes conflict. OS choice alone does not prove the setting is wrong. |
| ENV011 | Active environment metadata and the resolved interpreter path, normalized for platform case/symlinks. Unknown shim resolution is inconclusive. Never execute an interpreter discovered on PATH. |
| ENV012 | Proxy configuration and an explicitly requested, bounded reachability result. Without opt-in, collect redacted configuration only and mark reachability untested. |

For each rule, publish positive/negative/edge fixtures, evidence prerequisites, platform limitations,
manual advice and verification commands. An absent/failed/denied probe stays unknown or degraded;
do not convert it into a missing dependency or unreachable-service diagnosis.
Keep declared component dependencies and deterministic snapshot-only rule evaluation.

## Inspector and network contract

- Inspect Docker context metadata locally. A selected TCP/SSH context must never silently trigger a remote
  connection. ENV017's remote-context diagnostic remains a later rule, not an extra M3 feature.
- Preserve the default local probe and distinguish CLI absent, local daemon unavailable, permission denied,
  unsupported API and unknown version. Use trusted absolute CLI locations, fixed arguments and deadlines.
- Define the initial dependency catalog before coding: project markers, precise requirements, platform
  probe and unsupported cases. Bound manifest reads; parse data without executing project scripts.
- ENV012 uses the explicit `--probe-network` option defined by ADR 0005.
  Permit only the configured proxy host/port with a finite deadline, bounded count and cancellation.
  Use no proxy credentials, external target request or general connectivity scan. Invalid proxy URLs are
  invalid configuration, not proof the proxy is down. DNS is network work and requires the same opt-in.
- Fixtures, `explain` and `rules` perform no probes. Tests must prove a normal diagnosis initiates no remote
  connections even when Docker/proxy environment variables select remote endpoints.
- Redact home paths and credential-bearing URLs from snapshots, notices and errors. Preserve M2's
  documented Git identity disclosure; bundles with broader redaction remain M4.

## Registry, CLI and compatibility

One registry owns rule ID, component prerequisites, severity, title, evidence description, explanation,
manual steps, caveats and documentation links. Both `rules --json` and generated pages derive from it;
generation must be reproducible and CI must detect drift. `explain ENV006` works offline for existing
rules as well as new ones. Invalid IDs return a documented error, never empty success.

Preserve M2 report ordering, severity/exit-code mapping, `--component`, `--rule`, fixture behavior and
plain non-TTY output. Add snapshot evidence compatibly and validate real/fixture JSON against committed
schemas. Breaking field changes require an ADR, versioning and fixture migration guidance.

## Recorded decisions

project marker, package-manager evidence and registry JSON contract. It explicitly supersedes the affected
M2 restrictions while preserving offline defaults and defines missing/unsupported/partial evidence.
Do not amend accepted ADRs or ship unsupported claims as rule findings.
