## Scope and compatibility

Implement ENV-024–ENV-026: Bubble Tea with a plain fallback, Markdown export, a redacted bundle writer,
and `diagnose --from-bundle`. Include Markdown rendering explicitly in ENV-024; it currently has no
separate backlog item. Rules ENV013–ENV018, fix/apply/undo and signed packaging remain later milestones.

Preserve the nine collectors, twelve pure rules, immutable registry, evidence prerequisites, generated
rule pages, schema-v1 fixture support, deterministic finding ordering and existing JSON/exit behavior.
Ordinary `--json` still writes one report document to stdout; diagnostics/progress belong on stderr.
Diagnosis applies no fixes. Default collection remains offline, and proxy probing remains an explicit,
bounded live opt-in. No export or offline input enables a command supplied by a bundle.

## Renderer contract

- Interactive output is selected only when the required streams are terminals and terminal capabilities
  permit it. Define explicit plain-output/format flags, precedence and invalid combinations in ADR 0006.
  A redirect, pipe, `TERM=dumb`, `NO_COLOR` or explicit plain choice must have a documented fallback.
- Non-TTY/default plain output remains stable and contains no ANSI/cursor-control codes. JSON and
  Markdown bypass Bubble Tea, even in a terminal. Findings/collector failures retain their exit codes.
- Markdown includes severity, rule ID, evidence, limitations, manual suggestions and verification text
  from the same report/registry. Escape hostile labels, pipes, HTML, links and backtick/fence sequences;
  never turn captured commands or paths into executable behavior or active content.
- Do not present missing/denied/redacted evidence as a healthy result. Show degraded collectors and
  skipped rules alongside findings. Export progress/timings must not corrupt stdout formats.
- Resize, cancellation and output failure must restore terminal state and release timers/goroutines.
  An interactive rendering failure must have an explicit failure/fallback path, not discard the report.

## Bundle format and bounds

The zip is a versioned sharing format, separate from the existing fixture-directory snapshot contract.
Accepted v1 members are `manifest.json`, `snapshot.json`, `report.json`, `report.md`, `versions.json` and
optional structured `diagnostics.json`. A manifest records bundle/schema/tool versions, original capture
time, redaction policy, omitted evidence and member names/sizes/digests. Digests detect corruption;
they do not authenticate the machine or its author.

Retain the PLAN's under-2-MB requirement: define this as **fewer than 2,000,000 compressed bytes**.
ADR 0006 also limits total uncompressed member bytes to 8 MiB and entries to eight, with documented
per-member, JSON-depth/token and string bounds. Enforce limits before allocation/decompression where
possible and while streaming. A too-large capture fails explicitly; no partial archive or silently
truncated evidence is published. Stage output locally and replace it atomically after successful checks.

Read archives as data without extraction. Reject unsupported versions/methods, encrypted or ZIP64 input
unless explicitly supported, duplicate/unknown member names, directory/symlink entries, absolute paths,
drive/UNC names, backslash paths and traversal. Bound compressed data, directory metadata, decompressed
bytes and parse work independently. Verify member integrity and required schemas before diagnosis.
Never follow member paths, load a plugin, execute a verification/fix command or fetch a URL from a bundle.

## Export/redaction policy

Today's report redaction removes home paths and credential-bearing URLs, but retains effective Git
identity. Copying an existing JSON report is not a sharing policy. Define a separate allowlisted export
model before implementation, including the treatment of each field needed by ENV001–ENV012.

- Exclude raw environment values, tokens, usernames/emails, hostname, original home paths, process
  arguments, project file contents and arbitrary logs. Tool versions may be normalized metadata only.
- Sanitize or omit free text, paths, URL components, errors, notices, hints and report metadata before
  writing any member. Build report JSON/Markdown from sanitized evidence, rather than embedding the
  original report and relying on a final string-replacement pass.
- Preserve diagnostic distinctions where possible with nonidentifying facts or capture-local opaque
  replacements. If removing an identity/path loses required evidence, mark it omitted and skip or report
  the dependent rule as inconclusive; absence caused by redaction is not proof of a missing setting.
- Apply the same policy to optional tool diagnostics. `--include-logs` must not collect shell history,
  arbitrary files or unstructured command output; specify its allowlisted meaning or leave it unsupported.
- Test synthetic secrets/identities through every exported member, entry name, error path and stdout/
  stderr, including encoded URLs, Windows/Unix paths and degraded collectors. An unsupported field
  cannot fall back to raw export. Describe the actual policy and its limits; do not promise universal
  secret detection or that every arbitrary future string is safe to publish.

## Offline diagnosis and CLI behavior

`diagnose --from-bundle FILE` loads validated exported evidence and evaluates the current builtin registry
without running collectors, git/Docker, PATH tools, project scripts or network probes. Do not inspect
the receiving host to fill capture gaps. Retain original capture time/platform and identify captured
evidence, current evaluator version and omissions. Captured findings are reference data; recomputed
findings come from validated evidence, not the saved report's verdict or instructions.

Keep `--fixture-dir` unchanged. Define mutual exclusion with `--from-bundle` and live-evidence arguments
(`--port`, `--probe-network`, `--package-manager`). Output/evaluation filters may remain available.
Invalid usage exits 4; malformed/unsupported/bounded-out bundles or I/O failure exit 3. Valid offline
diagnosis uses the existing finding/degraded exit mapping 0/1/2/3, including redaction-related omissions.
The writer exits 0 when it successfully publishes an archive. The original diagnosis exit remains
reference metadata; the exported report records its recomputed exit, including omitted prerequisites.

## Acceptance evidence

- [x] Non-TTY, redirected stdout/stderr, dumb terminals, `NO_COLOR`, explicit plain, JSON and Markdown
  combinations have deterministic CLI tests; structured output contains no ANSI/progress contamination.
- [x] A real interactive run handles narrow width, resize, interrupt and output failure without leaving
  the terminal altered or retaining goroutines/timers after exit.
- [x] Markdown goldens cover every severity, collector errors, omitted evidence, hostile HTML/links,
  pipes/backticks and long paths, without changing finding order or severity.
- [x] Every successful bundle is below 2,000,000 compressed bytes; exact boundary/oversize cases,
  atomic output failure and independent decompression/entry/parse limits are tested.
- [x] The export policy removes synthetic tokens, raw environment values and identities from all members
  and diagnostics, including Git identity, errors and optional logs; unknown export fields fail closed.
- [x] Malformed, corrupt, duplicate, traversal/symlink, compressed-bomb and unsupported-version archives
  are rejected without extraction or unbounded memory growth.
- [x] Windows/Linux/macOS captures can be diagnosed on another OS offline; retained evidence reproduces
  applicable results while redacted prerequisites remain explicitly inconclusive.
- [x] Offline diagnosis executes no collectors/commands/network calls, ignores saved verdict instructions,
  distinguishes original capture/evaluator versions and rejects conflicting live-evidence flags.
- [x] Existing 172 golden cases, M3 JSON/schema/exit, registry generation, purity, probe and local race gates pass.
- [x] Terminal dependencies are pinned/audited; canonical local build/test/lint/race/docs gates pass.
- [x] Native Windows/Ubuntu/macOS GitHub CI passes for the final M4 branch.
- [x] One README screenshot is captured from the implemented interactive CLI with synthetic identities.
- [x] The M4 validation record maps every criterion to executed cases, commands, limits and skips.
